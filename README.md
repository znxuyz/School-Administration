# 行政工作進度追蹤系統

給學校行政老師使用的線上進度追蹤看板。老師用自己的 Google 帳號登入,建立行政計畫、
把工作拆成步驟,再逐項更新進度;主任看得到同處室的整體進度,逾期和久未更新的工作會被明顯標示,
避免行政工作被遺忘。

- **前端**:純 HTML / CSS / JavaScript,無需建置工具,可放在 GitHub Pages(免費);
  支援加到手機主畫面,離線也開得起來
- **後端**:Firebase — Firestore 資料庫 + Google 帳號登入(免費 Spark 方案,永久有效、不會休眠)
- **費用**:0 元。以十幾二十位老師的使用量來說,離免費額度的上限還很遠

---

## 功能

| 頁面 | 內容 |
|------|------|
| **總覽** | 進度看板,顯示範圍依角色而定(見下方權限說明)。統計磚顯示計畫總數 / 進行中 / 逾期 / 待更新 / 已完成,可依學年度、處室、負責人、**階段**、**公文所在單位**、狀態篩選,並可切換排序 |
| **搜尋** | 關鍵字找計畫,範圍包含步驟名稱與備註,**不受學年度等篩選限制** |
| **行事曆** | 月曆檢視,標出各計畫的開始日、結束日與結算期限,點日期看當天的完整項目 |
| **我的工作** | 建立與編輯自己的計畫、套用流程範本、拆解步驟、更新進度、登記公文流向 |
| **成員管理** | 僅管理員可見。維護可登入的 Email 白名單、處室、職稱與權限 |

### 四個固定階段

每個步驟都歸屬於一個階段,卡片上會用四格進度條顯示計畫走到哪一段:

| 階段 | 典型內容 |
|------|----------|
| **計畫** | 計畫書撰寫、經費概算表、簽陳校長核可、計畫函報上級 |
| **核定** | 上級核定函收文、核定金額確認、呈送領據、經費撥入確認 |
| **執行** | 採購請購、活動辦理、成果照片蒐集(搭配執行起訖日期) |
| **結案** | 核銷資料彙整、經費支出結算表、支出憑證(財務請購 / 薪水動簽 / 勞保勞退)、剩餘款繳回、結案函報上級 |

綠色=該階段已全部完成,藍色=目前所在階段,灰色=尚未開始,淡灰「—」=這個階段沒有安排步驟。

### 流程範本(不用每次重打)

新增計畫時可以直接套用範本,步驟會自動帶入,再依實際需要增刪:

- **標準行政計畫(含經費核銷)** — 13 個步驟的完整流程
- **無經費簡易計畫** — 6 個步驟
- **空白** — 全部自己建立

步驟名稱欄位也附有各階段的常用項目清單,可以直接點選,也可以自己打字。

**自己存範本**:管理員在計畫視窗按「**存成範本**」,就能把目前這份步驟清單
存成全校共用的範本,取個名字之後出現在範本選單裡(標示「自訂」)。

- 新增計畫時存得起來,**編輯既有計畫時也可以** —— 「這個計畫的步驟拆得剛好,
  以後大家照這個開」才是最常見的情境
- 只存流程本身(步驟名稱、階段、公文批次),不會把進度、日期、備註帶進範本
- 選到自訂範本時,管理員旁邊會出現「刪除範本」;刪掉不影響已經用它建立的計畫
- 組長、主任都套用得到,但只有管理員能新增或刪除,免得範本清單被各自的版本塞滿

每一列除了階段、名稱、狀態之外,還有:

| 欄位 / 按鈕 | 功能 |
|:----:|------|
| 備註 | 每個步驟下方的欄位,記「缺兩張發票」之類的提醒,會顯示在卡片上 |
| 同批 | 與上一個步驟併成同一份公文一起送(見下);每個階段的第一個步驟沒有可以併的上一份,會是停用狀態 |
| ↑ ↓ | 上移 / 下移。跨到相鄰階段時會自動改成該階段 |
| ＋ | **在這一列的下方插入**一個新步驟(不是只能加在最後) |
| ✕ | 刪除這一列 |

### 一起送的公文批次

實務上計畫書和概算表會併成一份公文送,結案的核銷、結算表、三種支出憑證、剩餘款繳回也是一起送。
在編輯器把步驟的「**同批**」打勾,就會和上一個步驟併成同一份公文:

- 展開明細時,同一批會被框在一起,標示「📎 一起送件・N 份文件併成一份公文,狀態一起更新」
- 這一批**共用一個位置選單**,改一次全部跟著動,流轉紀錄只記一筆
  (記成「核銷資料彙整 等 3 份」)
- **狀態也是整批同步**:同一份公文送出去,裡面的文件不會有的完成、有的沒完成,
  所以改其中一份的狀態,同批的其他份會跟著改(已標「本次不適用」的除外)
- 標準範本已經預設把「計畫書撰寫 + 經費概算表」和結案那六項各自設為一批
- 卡片上的「下一步」如果剛好是一批公文,兩份會兩個名字都寫出來、三份以上寫成
  「核銷資料彙整 等 6 份」;按旁邊的「✓ 完成」會**整批一起完成**

### 一鍵複製到新學年

行政工作大多每年重複。任何一張卡片上都有「**複製**」按鈕(不限自己的計畫,
新接手的老師也可以複製前任的計畫當範本),按下去會開一個預填好的新增視窗:

**照舊帶過來**:步驟名稱、所屬階段、公文批次設定、承辦處室、學期、備註說明

**一律歸零**:進度(第一批公文自動設為進行中,其餘未開始)、公文位置、
完成與起算日期、執行起訖日、核定經費、掃描檔連結

標題裡的學年度會自動往後推一年 ——「114 學年度課程計畫備查」變成「115 學年度課程計畫備查」,
不對的話在視窗裡直接改。**原本的計畫完全不會被更動**,存檔後總覽會自動切到新的學年度,
免得剛建好的計畫被目前的學年篩選擋住。

### 這次用不到的步驟

不是每個計畫都有剩餘款、都有薪資支出。把步驟的狀態改成「**本次不適用**」即可,
不需要刪掉步驟:

- 不列入進度分母(例如 13 個步驟中 2 個不適用,完成 11 個就是 100%)
- 不會被判逾期,「下一步」也會自動跳過
- 在批次內會標示「另 N 份本次不適用」,不隨整批一起送
- 步驟會保留在清單上並加上刪除線,看得出是「確認過不用辦」而不是「忘了做」

### 步驟不用各自填日期

日期只要在計畫上填一次(執行起訖日),步驟本身**沒有日期欄位**:

- 步驟改成「進行中」時自動記下起算日,顯示「已進行 9 天(2026-07-30 起)」
- 結案階段的步驟一律對照計畫的結算期限
- 退回「未開始」會把起算日清掉,重新計算

### 一份接一份的順序

公文是一份跑完才輪到下一份,系統照這個順序走:

- 套用範本或複製計畫時,**第一批公文預設就是「進行中」**(計畫書和概算表一起送,
  兩份就一起開始),後面全部「未開始」
- **前一批公文還沒完成,後面的步驟不能改成「進行中」或「已完成」** ——
  下拉選單裡這兩個選項會變灰,並標示「⏳ 等「上級核定函收文」完成」。
  例如把經費概算表改成已完成,不會讓呈送領據跳過核定函先開始
- 同一批一起送的文件彼此不用等(本來就是同一份公文)
- 一批公文**整批完成後,下一批會自動變成「進行中」**,老師只要按完成,
  下一步就自己亮起來並開始計算天數;下一批如果整批都「本次不適用」會自動跳過
- 還沒輪到的步驟仍然可以先標「**本次不適用**」——這次沒有剩餘款,一開始就標掉即可
- 完成的步驟會自動記下完成日期,顯示「✓ 2026-08-07 完成」;若改回未完成,日期會清掉

要跳過順序(例如補登舊資料)可以在「編輯」視窗裡直接改步驟狀態,那裡不受順序限制。

### 公文流向追蹤

公文位置是**掛在每一份文件(步驟)上的欄位**,不是整個計畫共用一個位置 ——
因為實務上概算表在校長室、領據在主計室、核銷單在縣府是同時發生的。

- 建立計畫時**不需要**設定位置,每個步驟預設都是「承辦人手上」
- 送出去之後,在卡片上展開明細,直接用該步驟後面的下拉選單改成送達的單位即可
- 改過位置的步驟會標上「已送至 ○○」,卡片最上方也會列出所有在外文件,例如
  「呈送領據 → 主計室」「採購/請購作業 → 總務處」
- 步驟標記為「已完成」後就不再列入在外文件

可選單位分成三組:承辦人手上、校內(校長室與六個處室)、校外單位(彰化縣政府教育處等)。
總覽頁可以用「公文所在」篩選,一眼看出**哪些公文正壓在主計室、哪些還在縣府**
(篩選選單只列真的送得出去的單位 ——「承辦人手上」代表沒送出去,篩它等於沒篩)。

每次改變位置系統都會**自動**記一筆到公文流轉紀錄(日期、哪份文件、從哪送到哪),
老師不必額外填任何表單,展開明細就能看到完整歷程。

紀錄是自動寫的,所以也給了兩個更正的方法:

- **同一天、同一份文件再改一次位置算「更正」**,直接蓋掉當天那一筆,
  不會因為選錯單位就多留一筆錯的;改回原本的位置那一筆會整個消失
- 隔天才發現選錯的話,流轉紀錄每一列右邊有 **✕** 可以刪掉那一筆
  (只有能編輯這個計畫的人看得到,刪紀錄不會動到文件目前的位置)

### 本週待辦

總覽最上面會列出**這一週該注意的是哪幾件**(統計磚只給數字,這裡給名字):

| 事由 | 什麼時候出現 |
|------|------|
| ⚠ 已逾期 | 結算期限或步驟期限已經過了(判定和「逾期」磚一致),並標出最早逾期的日期 |
| ⚠ 公文卡關 | 有文件停在同一個單位超過十天 |
| ✓ 要送結算 | 結算期限落在未來七天內 |
| ■ 執行結束 | 執行結束日落在未來七天內 |

- 一個計畫只列**最急的那一件**,同一個標題不會出現四次
- 已結案的計畫不會出現
- 點任何一列就會跳到那張卡片並展開;如果它正被篩選條件擋著,系統會先把條件清掉
- 最多列六件,其餘寫成「還有 N 件」
- 主任和管理員看得到別人的待辦,不是自己的會標上承辦人姓名

### 公文卡關示警

送出去的公文停在同一個單位太久,計畫本身還沒到期,光看狀態是看不出問題的。
系統會自動幫你算:

- 每份在外的文件都顯示**已送出幾天**,例如「已送至 主計室・3 天」
- 超過 **10 天**(可調)就轉成紅色並標「卡關」,卡片最上方的在外文件標籤同步變紅
- 統計磚多了一格「**公文卡關**」,點下去只看有文件卡住的計畫,再點一次取消

天數門檻在 `assets/config.js` 的 `STUCK_DAYS`。
功能上線前就送出去的舊資料沒有送出日期,系統會自動從公文流轉紀錄回推,一樣算得出天數。

### 結算期限自動加兩週

計畫通常是**執行結束後兩週內**要送結算,所以老師只要填「執行結束日期」,
**不用自己把送結算的時間算進去**:

- 系統自動把結算期限算成「執行結束日 + 14 天」,填日期時下方就會顯示算出來的日期
- 卡片上會顯示「結算期限 2026-10-05(還有 59 天)」
- 結案階段沒有自己填期限的步驟,一律對照這個結算期限,並標示「(結算期限)」
- 逾期判定也是用結算期限,所以執行結束後的兩週內不會被誤標成逾期

天數要改的話,調整 `assets/config.js` 的 `SETTLEMENT_GRACE_DAYS`。
個別步驟若有自己的期限,填了就以自己填的為準。

### 掃描檔雲端連結

紙本跑完掃描上傳學校雲端後,在計畫的「掃描檔雲端連結」欄位貼上網址,
卡片上就會出現「📁 掃描檔」按鈕,點了直接開新分頁。只接受 `http` / `https` 網址。

### 行事曆檢視

「行事曆」分頁用月曆呈現,一眼看出哪個月忙、哪個月要送結算:

| 標記 | 代表 |
|------|------|
| 🔵 **開始** | 計畫的執行開始日 |
| 🟠 **結束** | 計畫的執行結束日 |
| 🟢 **送結算** | 結算期限(執行結束日 + 兩週) |

- 月曆上方顯示「本月 1 件開始、1 件結束、1 件要送結算」
- **點任一天**,下方會列出當天的完整項目(計畫名稱、處室、承辦人、目前狀態)
- 已完成的計畫會用刪除線淡化,不會干擾還沒做完的
- 可以往前往後翻月,按「回到本月」跳回來
- 顯示範圍跟著角色走 —— 組長看自己的、主任看同處室、管理員看全校
- **手機版**格子只顯示彩色圓點(空間不夠放文字),點下去一樣看得到完整內容

### 定期計畫的下一次提醒

消防申報每半年一次、課程計畫每學年一次 —— 這類計畫在編輯視窗設定「**重複週期**」
(每半年 / 每學年),**結案之後**到了該再辦一次的時間,系統會主動提醒:

- 總覽最上方出現橫幅:「1 個定期計畫到了該再辦一次的時間」,可一鍵只看這些
- 該計畫的卡片上顯示「🔁 該辦下一次了・下一次建議在 2026-08-23 前開始」
- 按「**建立下一次**」直接開複製視窗,重複週期會由新的一次接手,舊的自動停止提醒
- 如果已經另外建好了,按「不再提醒」即可

提前多久開始提醒,調整 `assets/config.js` 的 `RECUR_LEAD_DAYS`(預設 30 天)。

### 刪除可以還原(垃圾桶)

刪除計畫**不會立刻消失**,而是移到垃圾桶:

- 平常的畫面(總覽、行事曆、我的工作、成員的名下件數)都不會顯示已刪除的
- 在總覽的篩選區勾選「**顯示垃圾桶**」就能看到,卡片上標示刪除日期與刪除人
- 按「**還原**」放回原位;確定不要了才按「永久刪除」(這次才是真的刪掉)

垃圾桶不會自動清空,要永久刪除得手動確認 —— 這樣誤刪一定救得回來。

### 搜尋

搜尋是**獨立的分頁**(總覽旁邊),不放在篩選列裡 —— 篩選是「在這個學年度裡縮小範圍」,
搜尋是「不知道在哪一年,直接找」,兩件事混在一起反而互相擋。

比對範圍包含:計畫名稱、計畫備註、承辦處室、承辦人姓名,以及**每個步驟的名稱與備註**。
所以可以直接搜「勞保勞退」找出哪些計畫還有這道手續,或搜「缺兩張發票」找出當初記下的問題。

- **不受學年度、處室、狀態等篩選限制**,往年的舊計畫一樣找得到
- 搜出來的卡片和總覽上的一模一樣,可以直接打勾完成、改公文位置、展開明細
- 切到這個分頁游標會自動停在輸入框,打字就開始找

### 職務交接

國小行政幾乎每年輪調。管理員在「成員管理」頁,每位有計畫的成員後面都有「**移交**」按鈕:

1. 選擇接手的同仁
2. 決定要不要**一併把承辦處室改成接手人的處室**(預設打勾)
3. 勾選要移交的計畫(預設全選,也可以只移交其中幾件)
4. 按「移交」

移交後由新承辦人負責更新進度,**計畫內容、步驟、公文流轉歷程完全保留**,
並在計畫的展開明細裡留下「職務交接紀錄」(何時、從誰交給誰、由誰辦理)。

> 第 2 步不是可有可無的:**承辦處室決定哪一位主任看得到這個計畫**。
> 交給別的處室的同仁卻沒改處室,會變成新承辦人的主任看不到、
> 原處室的主任反而還看得到。同處室內部的交接則不影響,取消勾選即可。

成員表的「名下計畫」欄位會顯示每個人手上有幾件;
把還有計畫的成員移出名單時,系統會先提醒你這些計畫將沒有人維護。

> **技術上的一個調整**:承辦人的判定從 Firebase 的內部 uid 改為 **Email**。
> 因為交接的對象可能還沒登入過系統,那時候拿不到對方的 uid;Email 在成員名單裡就有,
> 而且交接後仍然穩定。既有資料一律含有 `ownerEmail`,所以不受影響。

### 加到手機主畫面(PWA)

老師多半在手機上更新進度,系統支援加到主畫面,開起來像一般 App(全螢幕、沒有網址列):

| 手機 | 步驟 |
|------|------|
| **Android / Chrome** | 開啟網站 → 右上角 ⋮ → 「安裝應用程式」或「加到主畫面」 |
| **iPhone / Safari** | 開啟網站 → 下方分享鈕 → 「加入主畫面」 |

裝好之後主畫面會出現藍底白字的「行」圖示。另外:

- **沒有網路也打得開**畫面(顯示最後一次載入的內容),恢復連線後資料會自動同步
- 手機版的**篩選條件預設收起來**,只顯示「已套用 N 項」,不會佔掉整個螢幕
- 統計磚、步驟編輯器、對話框都有針對手機重新排版
- iPhone 的瀏海與底部指示條有做安全區處理,不會被遮住

### 其他省事的小設計

- **最常做的兩件事都在卡片上** — 「下一步:呈送領據」旁邊就是「✓ 完成」和公文位置選單,
  **不用每次展開明細**。按完成會讓一起送的整批同時完成、下一批自動接手變成「進行中」,
  卡片上的字馬上換成下一件事;位置選單改的是這一批文件現在在哪,一樣會自動記一筆流轉紀錄。
  全部做完會變成「✓ 全部步驟已完成」。要改備註、標「本次不適用」才需要展開
- **期限倒數** — 結案步驟在結算期限七天內會標成「(還有 3 天)」或「(今天到期)」,
  過期則標紅「(已逾期)」,不用自己算天數
- **進行中天數** — 步驟一改成「進行中」就開始計日,顯示「已進行 9 天」
- **統計磚就是篩選鈕** — 直接點上方的「逾期」磚就只看逾期的計畫,再點一次取消
- **承辦處室自動帶入** — 新增計畫時預設帶入你在成員名單登記的處室
- **排序預設照結算期限** — 最急的排最前面。若改成「最近更新」,每改一個步驟
  那張卡片就會跳到最上面,一件一件往下處理時清單會在手指下面亂動
- **看得出是誰改的** — 卡片上會寫「今天更新・林小明」,主任看同處室的計畫時
  才知道最後動的是承辦人自己還是管理員代改
- **記得上次看到哪裡** — 篩選條件、排序、展開了哪幾張卡片都存在這台裝置上,
  重新整理或隔天再開都還在(「顯示垃圾桶」除外,那是臨時檢視,不會被記住)。
  同一台電腦不同帳號分開記
- **提示用畫面下方的提示條** — 不再跳系統對話框。手機上按 alert 要多點一次才回得去,
  而且會擋住剛剛在改的那一列;提示條會自己消失,點一下可以提早關掉
- **螢幕閱讀器聽得到** — 提示條本身是 `aria-live` 區域;篩選之後也會播報「N 個計畫」,
  看不到清單長度的人才知道篩出幾件

**狀態如何判定**

| 狀態 | 條件 |
|------|------|
| 已完成 | 所有要辦的步驟都標記為「已完成」(本次不適用的不算) |
| 逾期 | 尚未完成,且結算期限(執行結束日 + 兩週)已經過去 |
| 待更新 | 尚未完成,且超過 14 天沒有任何更新(天數可在 `assets/config.js` 調整) |
| 進行中 | 以上皆非 |

## 建置步驟

### 1. Firebase 專案設定

在 [Firebase 主控台](https://console.firebase.google.com) 完成:

1. 建立專案(Google Analytics 選擇**停用**)
2. **Authentication** → 開始使用 → Sign-in method → 啟用 **Google**
3. **Firestore Database** → 建立資料庫 → Standard 版 → 位置 `asia-east1` → 正式版模式
4. **專案設定** → 你的應用程式 → 新增網頁應用程式 `</>` → 複製 `firebaseConfig`

把 `firebaseConfig` 填入 [`assets/config.js`](assets/config.js)。
這段設定屬於公開資訊,放在前端是 Firebase 的正常用法 —— 真正的存取控管由下一步的安全規則負責。

### 2. 套用安全規則

把 [`firestore.rules`](firestore.rules) 的內容整份貼到
**Firestore Database → 規則**,然後按「發布」。

沒有這一步的話,資料庫會維持在正式版模式的全鎖狀態(誰都讀不到),或是被改成測試模式的全開狀態(任何人都能讀寫)。**這一步不能跳過。**

規則除了擋權限,也會檢查欄位的基本合理性(學年度落在民國 90–200、金額不為負、
掃描檔連結只收 http/https、各種清單的筆數上限)。
唯一檢查不到的是 `steps` 與 `flow` 裡**每一筆的內容** ——
規則語言沒有迴圈,無法逐一走訪清單元素,那部分由前端存檔前整理。

### 3. 建立第一位管理員(重要)

系統規定只有管理員能維護名單,所以第一位管理員必須手動建立,否則沒有人進得去:

1. Firestore Database → 資料 → **開始建立集合**
2. 集合 ID 填 `allowlist`
3. 文件 ID 填**你的 Google 帳號 Email,全部小寫**(例:`principal@example.edu.tw`)
4. 新增以下欄位,型別都選 `string`:

   | 欄位 | 值 |
   |------|-----|
   | `name` | 你的姓名 |
   | `dept` | 處室,例:教務處 |
   | `title` | 職稱,例:教務主任(可留空字串) |
   | `role` | `admin` |

5. 儲存

之後其他老師就可以直接在系統的「成員管理」頁面新增,不必再回到主控台。

### 4. 部署到 GitHub Pages

1. GitHub repo → **Settings → Pages**
2. Source 選 **Deploy from a branch**,分支選本專案所在的分支,資料夾選 `/ (root)`
3. 儲存後等一兩分鐘,會得到網址,格式為 `https://<帳號>.github.io/School-Administration/`

### 5. 把網址加進 Firebase 授權網域(否則無法登入)

Firebase 預設只允許自家網域彈出登入視窗:

**Authentication → Settings(設定)→ 授權網域 → 新增網域**,填入 `<帳號>.github.io`

漏掉這一步,登入時會出現「這個網址尚未被加入 Firebase 的授權網域」。

## 資料結構

### `allowlist/{email}` — 可登入的成員(文件 ID 是小寫 Email)

| 欄位 | 型別 | 說明 |
|------|------|------|
| `name` | string | 姓名 |
| `dept` | string | 處室 |
| `title` | string | 職稱 |
| `role` | string | `staff`(組長)/ `director`(主任)/ `admin`(管理員)。舊資料的 `teacher` 會自動視為 `staff` |

### `plans/{autoId}` — 行政計畫

| 欄位 | 型別 | 說明 |
|------|------|------|
| `title` | string | 計畫名稱 |
| `dept` | string | 承辦處室 |
| `year` | number | 民國學年度,例 `115` |
| `term` | string | `1` 上學期 / `2` 下學期 / `0` 全學年 |
| `startDate` | string | 執行開始日 `YYYY-MM-DD`,可為空字串 |
| `endDate` | string | 執行結束日,同時作為整體期限 |
| `budget` | number | 核定經費,沒有就是 `0` |
| `recurring` | string | 重複週期:`""` 不重複 / `half` 每半年 / `year` 每學年 |
| `deletedAt` | string | 移到垃圾桶的日期,空字串代表沒被刪除 |
| `deletedBy` | string | 執行刪除的人 |
| `driveUrl` | string | 掃描檔的雲端連結,可為空字串 |
| `flow` | array | 公文流轉紀錄(位置變動時自動寫入),見下 |
| `handovers` | array | 職務交接紀錄,見下 |
| `note` | string | 備註 |
| `steps` | array | 步驟陣列,見下 |
| `ownerEmail` | string | **承辦人 Email(小寫)—— 權限判定依據**,職務交接時會改成接手人 |
| `ownerName` | string | 承辦人姓名(顯示用),交接時一併更新 |
| `ownerUid` | string | 建立者的 Firebase UID,僅供備查,不作為權限判定 |
| `createdAt` / `updatedAt` | timestamp | 建立 / 最後更新時間 |
| `updatedByName` | string | 最後更新的人,卡片上顯示成「今天更新・林小明」 |

每個 `steps` 元素:

```json
{ "title": "呈送領據", "stage": "approve", "status": "doing",
  "location": "主計室", "sentAt": "2026-07-25", "startedAt": "2026-07-30",
  "doneAt": "", "bundleWithPrev": false, "due": "", "note": "缺兩張發票" }
```

`stage` 為 `plan` / `approve` / `execute` / `close`,
`status` 為 `todo`(未開始)/ `doing`(進行中)/ `done`(已完成)/ `na`(本次不適用),
`location` 是**這份文件**目前所在的單位,空字串代表還在承辦人手上,
`sentAt` 是送到該單位的日期(自動填入,用來算卡關天數),
`startedAt` 是變成「進行中」的日期(自動填入,用來算已進行幾天),
`doneAt` 是標記完成的日期(自動填入),
`bundleWithPrev` 為 `true` 代表與上一個步驟併成同一份公文一起送,
`due` 已不再由介面填寫,舊資料若有值仍會優先用來判斷逾期。

每個 `flow` 元素(改變步驟位置時自動產生):

```json
{ "date": "2026-03-01", "step": "呈送領據", "from": "承辦人手上",
  "to": "主計室", "stage": "approve", "note": "" }
```

每個 `handovers` 元素(職務交接時自動產生):

```json
{ "date": "2026-08-08", "fromName": "陳美玲", "fromEmail": "chen@…",
  "toName": "張主任", "toEmail": "chang@…", "byName": "林小明" }
```

### `templates/{autoId}` — 自訂步驟範本(全校共用)

| 欄位 | 型別 | 說明 |
|------|------|------|
| `label` | string | 範本名稱,顯示在範本選單裡(最多 40 字) |
| `steps` | array | 每個元素是 `{ title, stage, bundleWithPrev }`,只存流程本身 |
| `createdBy` | string | 建立者姓名 |
| `createdAt` / `updatedAt` | timestamp | 建立 / 最後更新時間 |

每位成員都讀得到(所以套用得到),但只有管理員能新增與刪除。

**舊資料相容**:功能擴充前建立的計畫(沒有 `stage`、`flow`、`startDate`)仍然可以正常顯示 —— 沒有 `stage` 的步驟會歸到「執行」階段,沒有 `endDate` 時會沿用早期的 `dueDate` 欄位判斷逾期,早期存在計畫層級的 `location` 也會照常顯示。

學年度歸檔就靠 `year` 欄位 —— 舊學年的資料全部保留,在總覽頁切換學年度即可查閱。

**學年度清單會自動更新**:依當下日期推算(民國年,八月換學年),所以每年八月會自動
多出新的學年度,不用手動維護。清單同時會併入資料裡實際出現過的所有學年,
因此再舊的計畫也不會從篩選選單裡消失。

## 權限說明

系統有三種角色:

| 角色 | 看得到 | 能編輯 | 管理成員 / 職務交接 |
|------|--------|--------|:--------:|
| **組長** | 只有自己承辦的計畫 | 只有自己承辦的計畫 | ✗ |
| **主任** | 同處室所有人的計畫 | **只有自己承辦的計畫** | ✗ |
| **管理員** | 全校所有計畫 | 全校所有計畫 | ✓ |

主任的角色是**掌握同處室的進度**,不是代為填寫 —— 看得到同仁的計畫但不能修改,
責任歸屬留給承辦人。需要代為處理時請找管理員。

主任的範圍是依「計畫的承辦處室」比對「主任自己的處室」,所以**成員名單裡的處室要填正確**。

總覽頁的標題會照角色顯示範圍(「我的工作總覽」/「總務處工作總覽」/「全校行政工作總覽」),
免得誤以為資料不見了。

**管理員不能修改自己的角色** —— 避免不小心把自己降級後,整個系統沒有人管得動。
需要調整時請由另一位管理員操作,或回 Firebase 主控台手動改。

這些規則由 `firestore.rules` 在伺服器端強制執行,不是只靠前端隱藏按鈕 ——
即使有人繞過網頁直接呼叫 API,一樣擋得住。

## 常見問題

**老師說登入後顯示「尚未取得使用權限」**
該 Email 不在 `allowlist` 名單裡,或名單登記的 Email 與他登入用的 Google 帳號不同。
請到「成員管理」確認 Email 是否完全一致(系統一律以小寫比對)。

**點登入沒反應**
瀏覽器擋掉彈出視窗,請允許此網站的彈出視窗;或是第 5 步的授權網域沒設定。

**存成員或計畫時出現「Missing or insufficient permissions」**
Firestore 的安全規則還是舊版本。把專案裡的 `firestore.rules` 整份重新貼到
**Firestore Database → 規則** 並按「發布」。每次本專案更新了角色或欄位,
都要重貼一次規則,否則資料庫會擋下新的寫入。

**改了程式推上去,但網站看起來沒變 / 權限沒生效**
瀏覽器把舊的 `app.js`、`style.css` 快取住了。畫面右上角會顯示版本代號(例「金丹中期」),
和 `assets/config.js` 的 `APP_BUILD` 對一下就知道載到的是不是新版。
請老師**強制重新整理**:電腦版 `Ctrl + Shift + R`(Mac 是 `Cmd + Shift + R`);
手機版到瀏覽器設定清除網站資料,或改用無痕視窗開一次。

> **改版時執行 `./bump.sh`** —— 它會一次把版本號更新到所有需要的地方
> (config.js、index.html 兩處、app.js 的設定檔匯入、sw.js),不用手動一個個改:
>
> ```bash
> ./bump.sh        # 版本號自動加一
> ./bump.sh 12     # 直接指定
> ```
>
> **版本代號用單字表示**,畫面上不出現阿拉伯數字。一次改版換一個代號:
> 代號:朔 → 代號:曦 → 代號:晦 →⋯→ 代號:寂(五十個輪完再從「朔」開始)。
> 想換成別的主題,改 `assets/config.js` 的 `CODENAMES` 即可;
> 版本號本身照樣一直往上加(擋快取靠的是它),代號從第十一版起算。
>
> 已加到主畫面的老師不需要重裝,下次開啟就會自動換成新版。

**某位老師說看不到別人的計畫**
這是正常的:組長只看得到自己的計畫,主任只看得到同處室的。
若他應該看到更多,請在「成員管理」把角色調成主任或管理員,並確認處室填對。

**主任說看得到同仁的計畫卻沒有編輯按鈕**
這是刻意的設計。主任負責掌握進度,修改一律由承辦人自己來;
真的需要代為修改請找管理員。

**想改處室清單、公文單位、範本內容、常用步驟、「待更新」天數**
全部集中在 `assets/config.js`,不需要動到程式邏輯:

| 常數 | 控制的東西 |
|------|-----------|
| `DEPARTMENTS` | 建立計畫時可選的承辦處室 |
| `UNIT_GROUPS` | 公文可以送到的單位(校內處室、縣府等),分組顯示 |
| `STAGES` | 四個階段的名稱與說明文字 |
| `STEP_SUGGESTIONS` | 各階段步驟名稱欄位的下拉建議清單 |
| `ROLES` | 成員角色與各自的說明文字 |
| `TEMPLATES` | 新增計畫時可套用的流程範本(含哪些步驟要併成同一份公文) |
| `STALE_DAYS` | 幾天沒更新會被標成「待更新」 |
| `STUCK_DAYS` | 公文停在同一單位幾天算「卡關」(預設 10 天) |
| `RECURRENCES` | 可選的重複週期 |
| `RECUR_LEAD_DAYS` | 定期計畫提前幾天開始提醒(預設 30 天) |
| `SETTLEMENT_GRACE_DAYS` | 執行結束後幾天內要送結算(預設 14 天) |

改完存檔、推上 GitHub,約一分鐘後網站就會更新。

**想升級 Firebase SDK 版本**
修改 `assets/app.js` 最上方三行 import 的版本號即可。

## 後續可以加的功能

第一版刻意不做,需要時再加:

- 逾期或久未更新時寄 Email / LINE 提醒(需搭配 Cloud Functions 或 Apps Script)
- 匯出 Excel 或列印用的進度報表
- 步驟的附件上傳(Firebase Storage 目前要開帳單才能用,所以維持貼雲端連結)
- 公文文號欄位(可搜尋)
- 概算金額與核定金額分開,並記錄實際支用、剩餘款、已繳回
- 處室進度摘要表(每個人幾件、幾件逾期)給主任開會用
- 開啟 Firestore 離線快取,收訊不好時也能先把改動存在手機裡
