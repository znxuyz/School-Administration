# 行政工作進度追蹤系統

給學校行政老師使用的線上進度追蹤看板。老師用自己的 Google 帳號登入,建立行政計畫、
把工作拆成步驟,再逐項更新進度;全校同仁看得到彼此的進度,逾期和久未更新的工作會被明顯標示,
避免行政工作被遺忘。

- **前端**:純 HTML / CSS / JavaScript,無需建置工具,可放在 GitHub Pages(免費)
- **後端**:Firebase — Firestore 資料庫 + Google 帳號登入(免費 Spark 方案,永久有效、不會休眠)
- **費用**:0 元。以十幾二十位老師的使用量來說,離免費額度的上限還很遠

---

## 功能

| 頁面 | 內容 |
|------|------|
| **總覽** | 全校計畫進度看板。統計磚顯示計畫總數 / 進行中 / 逾期 / 待更新 / 已完成,可依學年度、處室、負責人、**階段**、**公文所在單位**、狀態、關鍵字篩選 |
| **我的工作** | 建立與編輯自己的計畫、套用流程範本、拆解步驟、更新進度、登記公文流向 |
| **成員管理** | 僅管理者可見。維護可登入的 Email 白名單、處室、職稱與權限 |

### 四個固定階段

每個步驟都歸屬於一個階段,卡片上會用四格進度條顯示計畫走到哪一段:

| 階段 | 典型內容 |
|------|----------|
| **計畫** | 計畫書撰寫、經費概算表、簽陳校長核可、計畫函報上級 |
| **核定** | 上級核定函收文、核定金額確認、呈送領據、經費撥入確認 |
| **執行** | 採購請購、活動辦理、成果照片蒐集(搭配執行起訖日期) |
| **結案** | 核銷資料彙整、經費支出結算表、支出憑證(財務請購 / 薪水動簽 / 勞保勞退)、剩餘款繳回、結案函報上級 |

綠色=該階段已全部完成,藍色=目前所在階段,灰色=尚未開始,淡灰「—」=這個階段沒有安排步驟。

### 流程範本(不用每次重打)

新增計畫時可以直接套用範本,步驟會自動帶入,再依實際需要增刪:

- **標準行政計畫(含經費核銷)** — 13 個步驟的完整流程
- **無經費簡易計畫** — 6 個步驟
- **空白** — 全部自己建立

步驟名稱欄位也附有各階段的常用項目清單,可以直接點選,也可以自己打字。

每一列右側有四個按鈕:

| 按鈕 | 功能 |
|:----:|------|
| ↑ ↓ | 上移 / 下移。跨到相鄰階段時會自動改成該階段 |
| ＋ | **在這一列的下方插入**一個新步驟(不是只能加在最後) |
| ✕ | 刪除這一列 |

### 一起送的公文批次

實務上計畫書和概算表會併成一份公文送,結案的核銷、結算表、三種支出憑證、剩餘款繳回也是一起送。
在編輯器把步驟的「**同批**」打勾,就會和上一個步驟併成同一份公文:

- 展開明細時,同一批會被框在一起,標示「📎 一起送件・N 份文件併成一份公文」
- 這一批**共用一個位置選單**,改一次全部跟著動,流轉紀錄只記一筆
  (記成「核銷資料彙整 等 3 份」)
- 標準範本已經預設把「計畫書撰寫 + 經費概算表」和結案那六項各自設為一批

### 這次用不到的步驟

不是每個計畫都有剩餘款、都有薪資支出。把步驟的狀態改成「**本次不適用**」即可,
不需要刪掉步驟:

- 不列入進度分母(例如 13 個步驟中 2 個不適用,完成 11 個就是 100%)
- 不會被判逾期,「下一步」也會自動跳過
- 在批次內會標示「另 N 份本次不適用」,不隨整批一起送
- 步驟會保留在清單上並加上刪除線,看得出是「確認過不用辦」而不是「忘了做」

### 自動接棒的進度

- 套用範本時,**第一個步驟預設就是「進行中」**,後面全部「未開始」
- 把某個步驟改成「已完成」時,**後面第一個「未開始」的步驟會自動變成「進行中」** ——
  老師只要按完成,下一步就自己亮起來
- 完成的步驟會自動記下完成日期,顯示「✓ 2026-08-07 完成」;若改回未完成,日期會清掉

### 公文流向追蹤

公文位置是**掛在每一份文件(步驟)上的欄位**,不是整個計畫共用一個位置 ——
因為實務上概算表在校長室、領據在會計室、核銷單在縣府是同時發生的。

- 建立計畫時**不需要**設定位置,每個步驟預設都是「承辦人手上」
- 送出去之後,在卡片上展開明細,直接用該步驟後面的下拉選單改成送達的單位即可
- 改過位置的步驟會標上「已送至 ○○」,卡片最上方也會列出所有在外文件,例如
  「呈送領據 → 會計室」「採購/請購作業 → 總務處」
- 步驟標記為「已完成」後就不再列入在外文件

可選單位分成三組:承辦人手上、校內九個處室、校外單位(彰化縣政府教育處等)。
總覽頁可以用「公文所在」篩選,一眼看出**哪些公文正壓在會計室、哪些還在縣府**。

每次改變位置系統都會**自動**記一筆到公文流轉紀錄(日期、哪份文件、從哪送到哪),
老師不必額外填任何表單,展開明細就能看到完整歷程。

### 結算期限自動加兩週

計畫通常是**執行結束後兩週內**要送結算,所以老師只要填「執行結束日期」,
**不用自己把送結算的時間算進去**:

- 系統自動把結算期限算成「執行結束日 + 14 天」,填日期時下方就會顯示算出來的日期
- 卡片上會顯示「結算期限 2026-10-05(還有 59 天)」
- 結案階段沒有自己填期限的步驟,一律對照這個結算期限,並標示「(結算期限)」
- 逾期判定也是用結算期限,所以執行結束後的兩週內不會被誤標成逾期

天數要改的話,調整 `assets/config.js` 的 `SETTLEMENT_GRACE_DAYS`。
個別步驟若有自己的期限,填了就以自己填的為準。

### 掃描檔雲端連結

紙本跑完掃描上傳學校雲端後,在計畫的「掃描檔雲端連結」欄位貼上網址,
卡片上就會出現「📁 掃描檔」按鈕,點了直接開新分頁。只接受 `http` / `https` 網址。

### 其他省事的小設計

- **下一步提示** — 卡片上直接標出「下一步:呈送領據」,不用展開就知道現在該做什麼;
  全部做完會變成「✓ 全部步驟已完成」
- **期限倒數** — 步驟期限在七天內會標成「(還有 3 天)」或「(今天到期)」,過期則標紅「(已逾期)」,
  不用自己算天數
- **統計磚就是篩選鈕** — 直接點上方的「逾期」磚就只看逾期的計畫,再點一次取消
- **承辦處室自動帶入** — 新增計畫時預設帶入你在成員名單登記的處室

**狀態如何判定**

| 狀態 | 條件 |
|------|------|
| 已完成 | 所有步驟都標記為「已完成」 |
| 逾期 | 尚未完成,且執行結束日或任一未完成步驟的期限已經過去 |
| 待更新 | 尚未完成,且超過 14 天沒有任何更新(天數可在 `assets/config.js` 調整) |
| 進行中 | 以上皆非 |

## 建置步驟

### 1. Firebase 專案設定

在 [Firebase 主控台](https://console.firebase.google.com) 完成:

1. 建立專案(Google Analytics 選擇**停用**)
2. **Authentication** → 開始使用 → Sign-in method → 啟用 **Google**
3. **Firestore Database** → 建立資料庫 → Standard 版 → 位置 `asia-east1` → 正式版模式
4. **專案設定** → 你的應用程式 → 新增網頁應用程式 `</>` → 複製 `firebaseConfig`

把 `firebaseConfig` 填入 [`assets/config.js`](assets/config.js)。
這段設定屬於公開資訊,放在前端是 Firebase 的正常用法 —— 真正的存取控管由下一步的安全規則負責。

### 2. 套用安全規則

把 [`firestore.rules`](firestore.rules) 的內容整份貼到
**Firestore Database → 規則**,然後按「發布」。

沒有這一步的話,資料庫會維持在正式版模式的全鎖狀態(誰都讀不到),或是被改成測試模式的全開狀態(任何人都能讀寫)。**這一步不能跳過。**

### 3. 建立第一位管理者(重要)

系統規定只有管理者能維護名單,所以第一位管理者必須手動建立,否則沒有人進得去:

1. Firestore Database → 資料 → **開始建立集合**
2. 集合 ID 填 `allowlist`
3. 文件 ID 填**你的 Google 帳號 Email,全部小寫**(例:`principal@example.edu.tw`)
4. 新增以下欄位,型別都選 `string`:

   | 欄位 | 值 |
   |------|-----|
   | `name` | 你的姓名 |
   | `dept` | 處室,例:教務處 |
   | `title` | 職稱,例:教務主任(可留空字串) |
   | `role` | `admin` |

5. 儲存

之後其他老師就可以直接在系統的「成員管理」頁面新增,不必再回到主控台。

### 4. 部署到 GitHub Pages

1. GitHub repo → **Settings → Pages**
2. Source 選 **Deploy from a branch**,分支選本專案所在的分支,資料夾選 `/ (root)`
3. 儲存後等一兩分鐘,會得到網址,格式為 `https://<帳號>.github.io/School-Administration/`

### 5. 把網址加進 Firebase 授權網域(否則無法登入)

Firebase 預設只允許自家網域彈出登入視窗:

**Authentication → Settings(設定)→ 授權網域 → 新增網域**,填入 `<帳號>.github.io`

漏掉這一步,登入時會出現「這個網址尚未被加入 Firebase 的授權網域」。

## 資料結構

### `allowlist/{email}` — 可登入的成員(文件 ID 是小寫 Email)

| 欄位 | 型別 | 說明 |
|------|------|------|
| `name` | string | 姓名 |
| `dept` | string | 處室 |
| `title` | string | 職稱 |
| `role` | string | `teacher` 或 `admin` |

### `plans/{autoId}` — 行政計畫

| 欄位 | 型別 | 說明 |
|------|------|------|
| `title` | string | 計畫名稱 |
| `dept` | string | 承辦處室 |
| `year` | number | 民國學年度,例 `115` |
| `term` | string | `1` 上學期 / `2` 下學期 / `0` 全學年 |
| `startDate` | string | 執行開始日 `YYYY-MM-DD`,可為空字串 |
| `endDate` | string | 執行結束日,同時作為整體期限 |
| `budget` | number | 核定經費,沒有就是 `0` |
| `driveUrl` | string | 掃描檔的雲端連結,可為空字串 |
| `flow` | array | 公文流轉紀錄(位置變動時自動寫入),見下 |
| `note` | string | 備註 |
| `steps` | array | 步驟陣列,見下 |
| `ownerUid` | string | 建立者的 Firebase UID(權限判定依據) |
| `ownerEmail` | string | 建立者 Email(小寫) |
| `ownerName` | string | 建立者姓名(顯示用) |
| `createdAt` / `updatedAt` | timestamp | 建立 / 最後更新時間 |

每個 `steps` 元素:

```json
{ "title": "呈送領據", "stage": "approve", "due": "2026-03-15",
  "status": "todo", "location": "會計室", "doneAt": "",
  "bundleWithPrev": false, "note": "" }
```

`stage` 為 `plan` / `approve` / `execute` / `close`,
`status` 為 `todo`(未開始)/ `doing`(進行中)/ `done`(已完成)/ `na`(本次不適用),
`location` 是**這份文件**目前所在的單位,空字串代表還在承辦人手上,
`doneAt` 是標記完成的日期(自動填入),
`bundleWithPrev` 為 `true` 代表與上一個步驟併成同一份公文一起送。

每個 `flow` 元素(改變步驟位置時自動產生):

```json
{ "date": "2026-03-01", "step": "呈送領據", "from": "承辦人手上",
  "to": "會計室", "stage": "approve", "note": "" }
```

**舊資料相容**:功能擴充前建立的計畫(沒有 `stage`、`flow`、`startDate`)仍然可以正常顯示 —— 沒有 `stage` 的步驟會歸到「執行」階段,沒有 `endDate` 時會沿用早期的 `dueDate` 欄位判斷逾期,早期存在計畫層級的 `location` 也會照常顯示。

學年度歸檔就靠 `year` 欄位 —— 舊學年的資料全部保留,在總覽頁切換學年度即可查閱。

## 權限說明

| 動作 | 一般成員 | 管理者 |
|------|:--------:|:------:|
| 登入系統 | 需在名單內 | 需在名單內 |
| 查看所有人的計畫 | ✓ | ✓ |
| 建立計畫 | ✓ | ✓ |
| 編輯 / 刪除自己的計畫 | ✓ | ✓ |
| 編輯 / 刪除他人的計畫 | ✗ | ✓ |
| 維護成員名單 | ✗ | ✓ |

這些規則由 `firestore.rules` 在伺服器端強制執行,不是只靠前端隱藏按鈕 ——
即使有人繞過網頁直接呼叫 API,一樣擋得住。

## 常見問題

**老師說登入後顯示「尚未取得使用權限」**
該 Email 不在 `allowlist` 名單裡,或名單登記的 Email 與他登入用的 Google 帳號不同。
請到「成員管理」確認 Email 是否完全一致(系統一律以小寫比對)。

**點登入沒反應**
瀏覽器擋掉彈出視窗,請允許此網站的彈出視窗;或是第 5 步的授權網域沒設定。

**想改處室清單、公文單位、範本內容、常用步驟、「待更新」天數**
全部集中在 `assets/config.js`,不需要動到程式邏輯:

| 常數 | 控制的東西 |
|------|-----------|
| `DEPARTMENTS` | 建立計畫時可選的承辦處室 |
| `UNIT_GROUPS` | 公文可以送到的單位(校內處室、縣府等),分組顯示 |
| `STAGES` | 四個階段的名稱與說明文字 |
| `STEP_SUGGESTIONS` | 各階段步驟名稱欄位的下拉建議清單 |
| `TEMPLATES` | 新增計畫時可套用的流程範本(含哪些步驟要併成同一份公文) |
| `STALE_DAYS` | 幾天沒更新會被標成「待更新」 |
| `SETTLEMENT_GRACE_DAYS` | 執行結束後幾天內要送結算(預設 14 天) |

改完存檔、推上 GitHub,約一分鐘後網站就會更新。

**想升級 Firebase SDK 版本**
修改 `assets/app.js` 最上方三行 import 的版本號即可。
